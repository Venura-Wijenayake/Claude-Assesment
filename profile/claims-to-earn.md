# Claims to Earn — the not-yet-true list

These are the résumé lines you *want* to be able to say but **can't defend yet**. They are not lies —
they're a to-do list. The moment one becomes literally, measurably true, it graduates to
`profile/facts.md` and goes on the résumé. This is the whole game: convert this list into that list.

| Claim you want to make | What makes it TRUE (and defensible) | Status |
|---|---|---|
| "Job Radar is used by real people" | ≥10 real users who aren't you/family, with usage you can show | ⬜ not yet |
| "I ship based on user feedback" | ≥1 documented change made because a real user asked | ⬜ not yet |
| "Lighthouse Open Health has real adoption" | ≥10 real users, or a partner/org that uses it | ⬜ not yet |
| "My project has traction" | analytics dashboard + testimonial(s) you can screen-share | ⬜ not yet |

## The credibility ladder (what each tier unlocks)

> **Honesty flag on this ladder itself:** the specific 10 / 50 / 100 cutoffs are a *reasoned
> framework*, not a published standard. Research found no source defining exact numeric thresholds.
> Treat as guidance, not law. What IS well-sourced: resumes with hard metrics see materially higher
> interview rates (~40% higher chance per Resume Now; quantified bullets ~3.2x callbacks), and the
> jump from **0 → any real users** is the single biggest credibility gain you can buy.

- **0 users** → claim only what you **built and deployed**, plus technical metrics (test coverage,
  latency, endpoints, data volume, uptime). **No adoption or impact claims at all.**
- **1–10 real users (pilot/beta)** → unlocks *"piloted/beta-tested with N users over [timeframe]"*,
  qualitative feedback, and *"iterated based on user feedback."* This is legitimate market-validation
  language. **This tier is the big one — it's the 0→1 that changes the story.**
- **10–50 users** → unlocks basic quantitative claims: task-success rate, which features got used,
  *"reduced [task] time for N users"*, a documented feedback loop, and a real testimonial quote.
- **50–100+** → unlocks trend/engagement metrics (retention, weekly actives, growth) and
  *"adopted by"* language that reads like genuine product work, not a class project.

**Be honestly small.** "Piloted with 8 tutoring students over 2 weeks" is *stronger* than a vague
"used by many" — it's specific, checkable, and proves you can get software in front of humans.

## The rule that protects you
Every time you're tempted to round up ("basically people use it"), stop and ask: *would this survive
the interviewer asking "show me"?* If not, it's a claim-to-earn, not a fact. You said it yourself —
you need proof you can actually defend. This page is where the honesty lives.
